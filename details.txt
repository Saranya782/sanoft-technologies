2. State and Context in React
Use React Context for shared global state such as:
Authenticated user info
Organization/team context
Notification/alert state
Use 
useState
 for local component state (e.g., form inputs, loading flags).
Use 
useReducer
 for complex state transitions (e.g., task list with filters).
Use 
useEffect
 for side effects like API calls and subscriptions.
Avoid prop-drilling — prefer Context or a state management library (e.g., Zustand or Redux Toolkit)
for deeply nested state.
Memoize expensive computations with 
useMemo
 and stable callbacks with 
useCallback 
.

4. Security — Login & Token Management
Never store JWTs in 
localStorage
 — use 
httpOnly
 cookies or in-memory storage.
Implement token refresh logic with short-lived access tokens and longer-lived refresh tokens.
Hash passwords using bcrypt (minimum 12 rounds) before storing — do not store plaintext
passwords.
Implement rate limiting on authentication endpoints to prevent brute-force attacks.
Validate all incoming request payloads using a schema validation library (e.g., 
in NestJS, 
Joi 
/
Zod
 in Express).
Protect against CORS misconfigurations — whitelist only trusted origins.
Return generic error messages on auth failures to avoid user enumeration:
✅ 
"
Invalid email or password"
No user found with this email"
❌ 
"
Validate and sanitize all user inputs server-side.
Use HTTPS for all communications (enforced on GCP).

5. Secret Management — Never Commit Secrets
.env
 files locally — add 
Store all sensitive configuration in environment variables.
Use

 to 
.gitignore

For GCP deployments, use:

Cloud Run environment variables or mounted secrets — never hardcode.
